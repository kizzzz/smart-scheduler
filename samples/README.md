# 导入功能演示样例

这些文件用于演示「导入已有排班表 → 一键体检」。每个样例的预期结论都由
`make_samples.py` 跑项目自己的 `validator.validate()` 断言过，不是手工编的。

重新生成：`python3 samples/make_samples.py`（图片样例需要 Pillow，缺了会跳过其余照常）。

| 文件 | 演示什么 | 预期结果 |
|---|---|---|
| `roster_long_ok.csv` | 标准长表（日期 / 班次 / 员工 三列） | 解析 14 格 / 64 人次，体检 **0 违规** |
| `roster_matrix_ok.csv` | 矩阵表（行=日期，列=早班/晚班） | 同上，验证布局自动探测 |
| `roster_long_violating.csv` | **导入体检的核心价值** | 体检 **5 条违规**，命中 R-01 / R-04 / R-07 / R-08 |
| `roster_messy.csv` | 脏数据容错 | 列名别名（星期/shift/人员）、日期别名（星期一/周一/二）、班次简写（早）、四种分隔符（顿号/半角逗号/全角逗号/空格）、小写工号（e03）、`E1` 简写；姓名「小王」与越界工号 `E99` 落入 `unresolved` |
| `roster_image_ok.png` | 图片识别链路 | 视觉模型识别后**强制人工确认**，实测 `glm-4v-flash` 在这张图上 14/14 格全对 |

## 违规样例是怎么构造的

在求解器产出的合规排班上做三处最小破坏，每处对应一条规则：

1. 周一早班移除所有具备店长值守资格的员工 → **R-01**（每班至少 1 名店长值守）
2. 周六晚班砍到 3 人 → **R-04**（周末每班至少 6 人）
3. 把 E01 塞进周三早班（E01 周三请假）→ **R-08**（请假日期绝对不得排班）

实际校验出 5 条违规——比注入的 3 处多，因为破坏产生了连带的 **R-07**（晚班次日早班）。
这正是「独立校验器」的意义：人改排班时想不到的连带违规，校验器会替你抓出来。

## 关于姓名匹配

员工档案（`backend/app/data.py`）只有工号 E01–E20 与技能，**没有姓名字段**。
所以任何非工号 token 一律进 `unresolved`，不做模糊匹配。

这不是能力不足，是刻意的：猜「小王」是谁就是编造数据，而排班基线一错，
后面所有校验结论都跟着错，且店长很难发现。宁可让用户手工指认。
